### 프로젝트 개요

AZIT는 러닝 크루의 일정을 관리하고, 위치 기반 출석 체크로 크루원의 참여를 높이는 러닝 크루 전용 플랫폼이다. IT 연합 동아리 CMC 18기에서 시작한 프로젝트로, 우수상을 수상했다. React Native 앱 안에서 React 웹을 WebView로 띄우는 하이브리드 구조로 개발했고, 현재 App Store와 Google Play에 출시해 운영하고 있다.

### 주요 기능

- **위치 기반 출석 체크**: 모임 장소 반경 100m 안에서, 모임 시간 앞뒤 1시간 동안만 출석할 수 있다.
- **캘린더 기반 일정**: 정기런과 번개런을 캘린더에서 구분해 보고, 시간이 겹치는 일정에는 참여할 수 없도록 검증한다.
- **크루 관리**: 운영진이 가입 승인·거절, 멤버 방출을 한 곳에서 처리한다.

### 개발 과정과 역할

프로젝트 초기에는 Vanilla Extract와 Storybook으로 디자인 시스템을 구축했다. 토큰을 `vars.css.ts`로 정의하고, recipes로 variant 스타일을 작성한 뒤 스타일 시트에서 variant 타입을 추출해 컴포넌트 props에 자동으로 반영되도록 구성했다. 버튼, 헤더, 드롭다운 등 공용 컴포넌트를 이 위에서 구현했다.

일정 화면에서는 react-calendar 없이 7일 단위 주간 캘린더를 직접 구현하고, 주간과 월간 캘린더가 스크롤과 제스처로 자연스럽게 전환되도록 만들었다. 날짜를 바꿀 때 목록이 깜빡이지 않도록 로딩 중에는 이전 데이터를 유지했고, Suspense와 에러 바운더리를 페이지 단위로 적용해 로딩·에러 상태를 일관되게 처리했다.

웹과 네이티브 사이 통신은 처음에 webview-bridge를 사용했지만, 이후 커스텀 JSON-RPC 브릿지 프로토콜로 교체했다. 브릿지 스펙을 패키지로 분리해 GitHub Packages에 배포하고, 네이티브 레포에 스펙 변경이 자동으로 반영되도록 워크플로를 구성했다. 카카오 로그인도 WebView 환경에서는 네이티브 SDK를 브릿지로 호출하도록 처리했다.

### 개발 환경 개선

CI를 lint, typecheck, build, test 잡으로 병렬 분리하고, PR 생성 시 자동으로 실행되도록 설정했다. 개발 환경에서는 MSW로 전체 API를 mock 처리해 백엔드 없이도 화면을 개발할 수 있게 했다. 또한 motion 의존성을 제거하고 CSS와 Web Animations API로 대체해 초기 번들 크기를 줄였다.
